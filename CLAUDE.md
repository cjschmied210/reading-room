# Reading Room (bridgeviewfolio.com)

A static site of class readings. Each reading is one self-contained page with five presentation modes (Page, Moving guide, Phrases, One word, Focus window), narration, and word highlighting. The homepage groups readings under a card per teacher. Hosted on Vercel; source on GitHub at `cjschmied210/reading-room`, which is public, so never commit keys or anything private.

The owner is a teacher, not a developer, and does not use Terminal. Run commands yourself, explain results in plain language, and when something needs their hands (a sign-in, a key) give click-by-click steps. Never ask them to paste an API key into chat: keys go in `.env` (gitignored), which they edit in TextEdit.

## Publishing a reading

The usual request is "here's a text, it's for Ms. X." Do all of this without being asked:

1. **Get the text.** For a Google Doc link, use the Google Drive connector's file-read tool with the document ID from the URL; the docs are private, so fetching the URL directly returns a sign-in page. For `.docx` or `.pdf` attachments, extract the text and keep paragraph breaks.
2. **Clean it** into a plain `.txt` file in the scratchpad, one blank line between paragraphs. Body text only: the title and byline go in `--title`, not the text. Remove anything that should not be read aloud: photo captions that pasted into the body, `*****` scene-break lines, markdown escapes (`\!`, `\[`), heading markup, link syntax. Do not correct the author's or translator's wording; if you spot a likely typo, leave it and mention it.
3. **Publish** with one command:
   ```bash
   node builder/publish.js --title "Title" --file /path/to/text.txt --teacher "Ms. Janavaris" --tts gemini
   ```
   This builds the page, generates narration (Gemini, key in `.env`), measures word timings, rebuilds the homepage, deploys to Vercel, commits, and pushes. Always include `--tts gemini` unless told otherwise; a reading without narration looks broken to this audience. Long texts take several minutes.
4. **Check it** before reporting back: the build log says `Word timings measured`, the homepage lists the title under the right teacher, and `https://bridgeviewfolio.com/<slug>/` loads with its audio file returning 200.
5. **Report** the link, the audio length, and anything you cut from or noticed in the text.

Conventions:
- Teacher names must match existing cards exactly ("Mr. Schmied", "Ms. Janavaris", "Ms. Kossis"); a new spelling creates a new card.
- Readings sort alphabetically by title within a card. Give an English/Spanish pair a shared prefix so they sit together, and distinct slugs: "Fish Cheeks (English)" / "Fish Cheeks (Español)" with `--slug fish-cheeks-english` / `--slug fish-cheeks-espanol`.
- `--slug` is a bare name, not a path. Reusing a slug overwrites that reading.

## Things that go wrong

- **Vercel "Missing authentication token" / "Not authorized".** The login lapses every few weeks. Run `npx vercel login`, give the owner the device URL and code it prints, wait for them to approve, then rerun the deploy (`npx vercel deploy --prod --cwd docs`) and commit and push, since `publish.js` stops at the failed deploy before it gets to git. A one-off "Not authorized" while still logged in is usually transient; retry once.
- **"Could not measure word timings".** The aligner lives in `.venv` (not in git). Recreate it with `python3 -m venv .venv && .venv/bin/pip install faster-whisper`, then run `node builder/rebuild.js --align <slug>`, rebuild the site, and deploy. Without measured timings a reading still plays on the Page view but has no highlighting and no read-aloud in the other modes; that fallback is deliberate, because estimated timings drift by seconds.
- **Gemini errors.** A 400 "API key not valid" means `.env` needs a new key (aistudio.google.com/apikey). A 404 naming a retired model means the model name in `builder/tts-gemini.js` needs updating to the one the error suggests.

## Changing the reader itself

- The reader is `src/app.jsx` and `src/style.css`; the homepage and footer are generated by `builder/build-site.js` and `builder/footer.js`. `docs/` and `out/*/index.html` are build output, so edit the sources, not those.
- After a change: `node builder/rebuild.js` (recompiles every reading, keeps its text, audio and timings, no API calls), then `node builder/build-site.js`, then deploy, commit, push.
- Do not rerun `--tts` on an existing reading to change something else about it: that regenerates the narration and costs API calls. To change only a title, edit `title` in the reading's baked data and recompose it the way `rebuild.js` does.
- Test in a browser before deploying. Serve `docs/` with `npx http-server` rather than `python3 -m http.server`: Python's server does not support byte ranges, so audio seeking silently restarts from zero and the stepped modes look broken when they are not.
- `docs/.vercel/` links the folder to the Vercel project; never delete it.

## What not to publish

The site is public with no login (pages are `noindex`, which only keeps them out of search). Literary excerpts for class are the norm. Licensed assessment material, such as DIBELS fluency passages, must not go on the site: its license is internal-use only and public exposure defeats the assessment. If a text looks like a test instrument, stop and ask.
